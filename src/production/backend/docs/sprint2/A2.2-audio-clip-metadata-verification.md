# A2.2 — Audio Clip Storage: Metadata & Detection-Linking Verification

**Task:** A2.2 (Shared, under A2 – Audio Clip Storage and Detection Linking)
**Sprint:** Sprint 2 — Backend

## Objective
Define metadata/index requirements for audio clip storage and verify detection-to-audio
lookup performance/consistency, building on the existing `POST /api/audio/upload` route
and `Detection.audioClip` field.

## What was tested
- Uploaded a real test audio file (`test_sample.wav`) via `POST /api/audio/upload`.
  - The multipart field required an explicit `;type=audio/wav` to pass content-type
    validation.
  - Result: `200 OK` — upload succeeded, returned
    `upload_id: 6aab7eb2305888e0d16f5d5c`, stored in the `AudioUploads` collection.
- Attempted to create a detection referencing this upload via `POST /detections`, using
  a fully valid payload (all required fields: timestamp, sensorId, species,
  microphoneLLA, animalEstLLA, animalTrueLLA, animalLLAUncertainty, audioClip,
  confidence, sampleRate).
  - Result: `403 Forbidden` — `"Budget is not configured for 'detections'
    (monthly_limit=0)."`, enforced by the `enforce_and_consume` budget-check dependency
    ahead of normal detection creation.
- Separately, checked `GET /api/admin/budget/usage?service=detection`.
  - Result: `500 Internal Server Error`.
  - Server logs show the exact cause: `admin_budget.py` line 46 calls
    `get_usage(service=service, month_key=month_key)`, but `get_usage()` does not accept
    a `month_key` argument — `TypeError: get_usage() got an unexpected keyword
    argument 'month_key'`.
- Workaround (validated previously): inserted a test detection directly via the mongo
  shell with `audioClip` set to a valid upload_id, then confirmed via
  `GET /detections/{id}` that `audioClip` resolves correctly back to the uploaded file
  reference.

## Findings
1. **Two separate budget-related problems were found. They are independent of each
   other.**
   - `POST /detections` returns `403` because no budget rule is configured for
     `"detections"` yet. `enforce_and_consume()` (the dependency guarding
     `POST /detections`) never calls `get_usage()`. It does its own `limit <= 0` check,
     and with no rule set the limit is 0. This is a config gap, fixable via
     `POST /admin/budget/limits`.
   - `GET /api/admin/budget/usage` returns `500` because of a function signature
     mismatch (`month_key` not accepted by `get_usage()`) in
     `app/routers/admin_budget.py` line 46. This is a code bug, and it is not what
     causes the `403`.
2. **No automatic audio linking exists yet.** There is no code that links
   `Detection.audioClip` to `AudioUploads._id` automatically — that is the
   responsibility of A2.1, not yet implemented at time of testing.
3. **Manual linkage works correctly.** Once a detection is inserted with `audioClip`
   set to a valid `upload_id`, retrieval via `GET /detections/{id}` resolves it
   correctly — confirming the underlying storage/retrieval path is sound. The only
   things still open are automatic linking (A2.1) and the two budget issues below.
4. **Proposed requirement (for A2.1):**
   - Store the `upload_id` in `audioClip` at detection-creation time.
   - Validate that the referenced upload exists before persisting the detection.
   - Add a retrieval helper so lookups don't require manual mongo queries.

## Status
Metadata/index requirement documented above. Detection-to-audio lookup verified working
end-to-end (upload → manual link → retrieval). Automatic linking is out of scope for
A2.2 and depends on A2.1. Normal API-path testing of detection creation is currently
blocked by the missing budget rule for `"detections"` (Blocker 1 below).

## Blocking issues to flag (out of A2.2 scope, need owner)

### Blocker 1 — `POST /detections` returns 403 (config gap)
- `enforce_and_consume()` does its own `limit <= 0` check and never calls `get_usage()`.
- No budget rule is configured for `"detections"`, so every request is rejected with
  `403`.
- Fix: configure a budget limit for `"detections"` via `POST /admin/budget/limits`.
  No code change is needed.
- This is the one that blocks testing for other Sprint 2 tasks that depend on
  `POST /detections` (A1, A3, A4, A5), so it is worth raising as a shared blocker.

### Blocker 2 — `GET /api/admin/budget/usage` returns 500 (code bug)
- Root cause: `app/routers/admin_budget.py` line 46 passes `month_key` to
  `get_usage()`, which does not accept that argument.
- This is independent of Blocker 1. Fixing it will not unblock detection creation.
- Needs a code fix from the owner of the budget module.

## Next steps / dependencies
- A2.1 to implement automatic `audioClip` population and validation.
- Someone with admin access to configure the `"detections"` budget rule
  (`POST /admin/budget/limits`), then re-test detection creation through the normal API.
- The `get_usage()` / `month_key` bug needs a fix owner, tracked separately from the
  above.
