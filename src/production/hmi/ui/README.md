# Project Echo HMI

This directory is the deployable HMI package. It runs one Express server that
serves static browser pages and same-origin API routes. Server code uses
CommonJS. Browser code under `public/` uses ES modules.

## Setup

Use Node.js 22 and npm 10 from this directory:

```powershell
cd src/production/hmi/ui
npm ci
npm test
node server.js
```

Open `http://localhost:3000` or `http://localhost:3000/login`.

`node_modules/` is generated by `npm ci` and ignored by Git. Do not document or
commit generated dependencies as source files. Docker installs production
dependencies with `npm ci --omit=dev` and starts `node server.js`.

## Environment

The HMI reads local settings from `.env` in this directory. Copy
`.env.example` to `.env` when you need values that differ from the defaults.
The common local values are:

```env
API_HOST=localhost
API_PORT=9000
CLIENT_URL=http://localhost:3000
COOKIE_SECRET=replace-with-a-long-random-value
```

The HMI defaults to port 3000. `API_HOST` and `API_PORT` identify the FastAPI
Backend that the HMI proxies to. `CLIENT_URL` is the public browser-facing
HMI URL used by redirects and email links. Backend, Redis, MongoDB, email,
and payment settings are read from environment variables by
`server/config/environment.js` and the route modules.

Runtime notes:

- `COOKIE_SECRET` should be stable and random anywhere sessions must survive
  a restart.
- Docker supplies service hostnames such as the Backend, Redis, and MongoDB
  hosts through the container environment.
- Restart the HMI process after changing `.env`.

Troubleshooting:

- **Cannot connect to Backend** - confirm the Backend is running and
  `API_HOST`/`API_PORT` point to it.
- **Sessions reset after restart** - set a stable `COOKIE_SECRET`.
- **Payment checkout is unavailable** - confirm the Backend payment provider
  environment is configured, then restart the Backend and HMI.
- **Changes to `.env` do not appear** - restart the HMI process or
  rebuild/restart the container.

## Structure

```text
ui/
|- server.js                  Express bootstrap
|- server/                    CommonJS app, config, middleware, routes, services
|- public/
|  |- pages/                  HTML pages served by legacy-compatible routes
|  |- features/               Feature-owned browser modules and styles
|  |- shared/                 Shared browser HTTP, UI, and admin shell modules
|  |- assets/                 Static fonts, images, and styles
|  `- vendor/                 Vendored browser libraries
`- tests/
   |- browser/                Browser-module and static-dependency tests
   |- server/                 Express route and server-module tests
   `- structure/              Package, layout, and removal-audit tests
```

## Navigating the codebase

New here? Read this section top to bottom. Already working here? Skip to
"Common tasks".

### Where to start

1. `server.js` - bootstrap only. It loads config, connects Redis and MongoDB,
   creates the app, and listens. Start here to see how the process starts.
2. `server/app.js` - Express composition. It registers middleware and routes
   in dependency order. Start here to see what the server does.
3. `server/routes/` - one registrar per domain (auth, map, sensor,
   notifications, payments, admin, pages, proxy). Start here to find or add
   an endpoint.
4. `public/pages/` - HTML entry points grouped by `auth/`, `map/`, `admin/`.
   Start here to find or add a page.
5. `public/features/` - feature-owned browser code (`map`, `audio`,
   `detections`, `payments`, `sensor-health`). Start here to change UI
   behavior.

### How a request travels

```text
Browser page (public/pages/.../*.html)
  -> feature module (public/features/<name>/...)
  -> shared same-origin client (public/shared/http/routes.js)
  -> Express domain route (server/routes/*.routes.js)
  -> shared Backend client (server/services/apiClient.js)
  -> FastAPI
```

Rules that fall out of this path: browser code never calls a Backend host
directly (same-origin only); Express routes reuse `server/services/apiClient.js`
instead of creating page-specific HTTP clients; session checks live at the
Express seam.

### Directory map

- `server/config/` - environment parsing, cookie-session and CSP options.
- `server/middleware/` - session guards and auth checks.
- `server/services/` - shared Backend client, Redis, MongoDB, notifications,
  email, and the legacy Mongoose user model.
- `public/shared/` - shared browser code: `http/` (API client, fetch
  helper), `ui/` (errors, toasts, DOM helpers), `admin/` (layout loader,
  page-state helper, header/sidebar/footer fragments).
- `public/assets/` - images, fonts, global styles used at runtime.
- `public/vendor/` - third-party bundles stored in the repo (OpenLayers,
  admin theme). Tabler CSS and its `fonts/` directory move as one group.
- `tests/browser/` - browser feature and static-dependency tests.
- `tests/server/` - Express route, session, and composition tests.
- `tests/structure/` - package hygiene, layout, and removal-audit tests.

### Common tasks

- **Add a page**: put the HTML under `public/pages/<area>/`, register its URL
  in `server/routes/pages.routes.js` (plus a legacy alias if an old URL must
  keep working), and add the URL/file pair to
  `tests/server/page-route-manifest.test.mjs`.
- **Add an API route**: add it to the matching registrar in `server/routes/`,
  keep the order rules in `server/app.js` (raw webhook before JSON parsing,
  `/index.html` guard before static files, specific routes before wildcard
  proxies), go through `apiClient`, and put session checks on it from day one.
- **Add a browser feature**: create `public/features/<name>/`, import the
  shared client from `/shared/http/routes.js` and error helpers from
  `/shared/ui/hmi-utils.js`. One module owns each map, layer, timer, stream,
  and object URL, and cleans it up on change, failure, and teardown.
- **Add shared browser code**: only when two or more features need it;
  otherwise keep it in the feature. A seam with one consumer is a guess.
- **Remove a file**: prove zero consumers first (route mapping, HTML/JS/CSS
  reference, server read, test, Dockerfile, docs), following the pattern in
  `tests/structure/removal-audit.test.mjs`. Never delete on naming or age
  alone.

### Gotchas for newcomers

- Server files are CommonJS (`require`); browser files are ES modules
  (`import`). Do not set the package to `"type": "module"`.
- Route registration order changes behavior (sensor-specific routes must run
  before the broad `/sensors*` proxy). The manifest and precedence tests
  guard this.
- The static-dependency test crawls every active page and fails on any new
  missing local file, so update imports and HTML references in the same
  change as any file move.
- Tests never call live services: network, Redis, MongoDB, MQTT, media,
  payments, and email are mocked at their boundaries.
