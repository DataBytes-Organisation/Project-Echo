# Project Echo Development Rules

## Branch Naming Convention

Please follow the Project Echo GitHub branch naming convention whenever you begin an onboarding task, sprint task, bug fix, documentation update, or any other development work.

Use the following format:
`[Component Abbreviation]/[Your Initials]/[Task Name]`

**Component Abbreviations:**
*   `EE` – Engine Team
*   `EH` – HMI Team
*   `EI` – IoT Team
*   `EB` – Backend Team

**Example:**
If completing a model benchmarking task for the Engine Team, the branch name would be: `EE/KF/Benchmarking-Models`

**Important Guidelines:**
*   ✅ Create a new branch for each task.
*   ✅ Create your branch from the latest `main` branch.
*   ✅ Use a short and clear task name.
*   ✅ Do not work or commit directly to `main`.
*   ✅ Do not create a separate fork of the repository.
*   ✅ When the work is complete, push your branch and create a pull request to merge it into `main`.
